# Workflow: Nghiên cứu tính năng KiotViet → Lộ trình cho Postie

## Mục tiêu
Nghiên cứu tính năng của kiotviet.vn (3 mảng ưu tiên: Bán hàng POS, Quản lý kho, Báo cáo + kết nối), phân tích khoảng cách với codebase Postie hiện tại, và xuất báo cáo lộ trình `docs/kiotviet-roadmap.md`. **Không implement code** — chỉ nghiên cứu + tài liệu.

## Subagent topology (7 subagents)

**Phase 1 — Nghiên cứu KiotViet (3 subagents song song, độc lập):**
| Tên | Phạm vi | Kết quả trả về |
|---|---|---|
| `research-pos` | Bán tại quầy, thanh toán đa kênh, ca làm việc, in hóa đơn/barcode, giảm giá/coupon, đặt hàng, bán online | `KiotFeature[]` |
| `research-kho` | Hàng hóa, danh mục, tồn kho, kiểm kê, chuyển kho, nhà cung cấp, đặt hàng nhập | `KiotFeature[]` |
| `research-baocao` | Báo cáo doanh thu/lợi nhuận/tồn kho, hóa đơn điện tử, kết nối sàn TMĐT, chuỗi cửa hàng | `KiotFeature[]` |

Mỗi researcher tự fetch các trang kiotviet.vn (trang chủ, trang tính năng) bằng công cụ web của mình. `KiotFeature = { name, description, source, importance: core|useful|advanced }`.

**Phase 2 — Phân tích khoảng cách (1 subagent, barrier hợp lệ — cần đủ danh sách tính năng):**
- `gap-analyst`: đọc `db/schema.sql`, `electron/db/repositories/*`, `src/renderer/*` của Postie, map từng tính năng KiotViet → `{ feature, status: have|partial|missing, evidence (path trong code), effort: S|M|L, value, suggestion }`
- Mỗi gap được `report()` ngay khi có → hiển thị live trong bảng dashboard `gap-table` (columns: feature/status/effort/value)

**Phase 3 — Tổng hợp lộ trình (1 subagent):**
- `synthesizer`: viết `docs/kiotviet-roadmap.md` (tiếng Việt): tổng quan KiotViet, bảng tính năng theo 3 mảng, gap analysis có trích dẫn file, lộ trình P0/P1/P2 với gợi ý schema/UI cụ thể cho Postie

**Phase 4 — Đọc lại độc lập (1 subagent + fixer có điều kiện, cap 1 round):**
- `report-reader`: fresh-eyes đọc báo cáo, trả về `{ ok, comments[] }` — tìm chỗ không rõ, thiếu, không được text hỗ trợ
- `doc-fixer`: chỉ chạy nếu `!ok`, sửa báo cáo theo comments

**Phase 5 — Xuất bản:**
- `artifact.file("roadmap", "docs/kiotviet-roadmap.md", { primary: true })` + return `WorkflowReport`

## Kết quả người dùng nhận được
1. File `docs/kiotviet-roadmap.md` trong dự án (deliverable chính)
2. Bảng gap live trong lúc chạy (dashboard)
3. Return: conclusion + verified/notCovered (verified = gap analyst đọc code trực tiếp; notCovered = không xác minh tính năng KiotViet ngoài trang công khai, không chạy build)

## Lý do thiết kế
- 3 researcher song song vì 3 mảng độc lập nhau; barrier trước Phase 2 hợp lệ vì gap-analyst cần đủ danh sách
- Survey-type deliverable → kiểm chứng bằng 1 independent read (không per-finding confirmer — đúng budget §1/§3 của skill)
- Không dùng `world.run` — không có check deterministic nào áp dụng cho nghiên cứu+tài liệu
- Ghi chú: các plugin frontend-design/browser-use/image-search được tham chiếu là gợi ý năng lực; workflow dùng web fetch của subagent; phần thiết kế UI trong lộ trình sẽ gợi ý làm bằng frontend-design skill ở bước sau
